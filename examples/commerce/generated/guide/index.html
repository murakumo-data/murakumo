The duckdb accounts, roles and credentials the platform runs as.

1.1 Nothing to create: the warehouse is a file

Why: DuckDB keeps the whole warehouse in one file, commerce.duckdb, created the first time anything is written to it. Each environment with a database of its own gets its own file.

duckdb commerce.duckdb -c 'select 42'

You should see: 42, and a new file commerce.duckdb in the project folder.

4. The raw layer

The raw tables, what each column holds, and the SQL that loads the landed files into them, each table its own way (full, append or incremental). Run the loads from the project folder, after the files have landed.

4.1 Create the schemas and the raw tables

Why: Raw tables hold the data as it arrived, plus when it was loaded (_ingested_at) and from which batch (_batch_id). Nothing ever changes a raw row except the load. Every statement can run again safely.

    coalesce(y.days_active, 0) + case when t.activity_date is null then 0 else 1 end as days_active,
    coalesce(t.activity_date, y.last_active) as last_active,
    run.day as snapshot_date
from today as t
full outer join yesterday as y
    on t.customer_id = y.customer_id
cross join run;
