# 6. Running it

Building the models, on demand and on schedule, and rebuilding when needed.

## 6.1 Build everything with dbt

**Why:** `dbt build` runs every model, snapshot and test in dependency order. Each environment is a target in profiles.yml.

```bash
dbt build --project-dir generated/dbt --profiles-dir generated/dbt --target dev
```

**You should see:** `Completed successfully` and a summary with `ERROR=0`.

## 6.3 Schedule the builds

**Why:** Each schedule rebuilds only what it refreshes, through its dbt selector (generated/dbt/selectors.yml). The airflow pipelines run them on time, fetching and loading first.

| Schedule | Cron | What | Command |
| --- | --- | --- | --- |
| hourly_sales | 0 * * * * | Order lines and customers, every hour | dbt build --selector hourly_sales |
| nightly | 0 6 * * * |  | dbt build --selector nightly |

## 6.4 Backfill and rebuild

**Why:** Incremental tables pick up only what is new. To rebuild a table from all of raw, refresh it in full; to recompute a cumulative table's day, give the day.

```bash
dbt build --project-dir generated/dbt --profiles-dir generated/dbt --target dev --full-refresh --select <model>
dbt build --project-dir generated/dbt --profiles-dir generated/dbt --target dev --vars '{"run_date": "2026-01-31"}' --select <cumulative model>
```
