# 8. CI/CD

Checking each change, and deploying each environment when its branch changes.

## 8.1 Add the CI workflow

**Why:** Each pull request is checked (the model validated, the project built and tested); merging into an environment's branch deploys that environment. Commit it in .github/workflows.

.github/workflows/murakumo.yml:

```yaml
# Written by `murakumo ci`. It is yours to change: Murakumo will not overwrite it without asking.
# Checks that the model, its generated code and its migrations agree, and that the dbt project builds.
name: murakumo
on:
  pull_request:
  push:
    branches:
      - main
  workflow_dispatch:
jobs:
  check:
    name: Model, code and migrations agree
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: examples/commerce
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: astral-sh/setup-uv@v6
      - name: Install Murakumo
        run: uv tool install "murakumo[duckdb,verify]==0.9.0"
      - name: The pull request follows the flow
        if: github.event_name == 'pull_request'
        env:
          HEAD_BRANCH: ${{ github.head_ref }}
          BASE_BRANCH: ${{ github.base_ref }}
        run: murakumo branch check --head "$HEAD_BRANCH" --base "$BASE_BRANCH"
      - name: Model changes and their impact
        if: github.event_name == 'pull_request'
        env:
          BASE_BRANCH: ${{ github.base_ref }}
        run: murakumo diff "origin/$BASE_BRANCH" --format markdown >> "$GITHUB_STEP_SUMMARY"
      - name: Validate the model
        run: murakumo validate --strict
      - name: Generated code is up to date
        run: murakumo generate --check
      - name: Migrations are up to date
        run: murakumo migrate --check
      - name: Build and test on DuckDB
        run: murakumo verify
```

**You should see:** The workflow's checks on your next pull request.
